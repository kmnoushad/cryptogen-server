# v6.9.28 — fade worker idle poll reduction

The external worker polls Supabase every 10 seconds when it has no active
execution intents (previously every five seconds). Active OPEN, RUNNER,
and SUBMITTING intents still use the existing five-second interval for
exchange protection and reconciliation. The 10-second idle interval remains
below the 30-second database lease and 60-second Telegram status freshness
windows. This affects only future traffic and cannot undo egress already used.

The Railway scanners and other Supabase callers are unchanged. Check the
organization Egress detail and API path report before attributing the entire
usage to this worker or deciding on further optimizations.
