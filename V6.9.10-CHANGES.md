# v6.9.10 — paper execution and manual-alert correctness

The previous paper evaluator could reuse pre-entry candle extremes, place a breakeven stop above the market, and fill a stop at a level skipped by a gap. The open-position risk check usually received too few candles to run. These defects prevent reliable strategy evaluation.

This change fixes those paths without changing the impulse, reclaim, volume, BTC-regime or momentum-fade thresholds. It does not establish a profitable trading edge.

## Execution model

New entries store `setup.executionModel = "closed-bar-v2"`. New closures also store `setup.exitExecutionModel`, including closures of positions opened before the upgrade. Existing closed rows are not rewritten. Compare cohorts by both fields when evaluating performance; do not pool old and new results as one unchanged experiment.

- Entirely pre-entry candles are excluded. If entry occurs partway through a one-minute candle, only that candle's close is used. Its high/low cannot be assigned to the period after entry. A close beyond a stop still closes the paper trade at that observed price with assumed slippage.
- This first-candle policy is an explicit approximation: a post-entry stop or target touch that reverses before the close is unobservable in the available data and may be missed. Trade/tick data captured from entry onward is needed to remove this limitation. Skipping uncertain extremes must not be interpreted as improved strategy profitability.
- For complete candles, simultaneous stop and target touches retain conservative stop-first ordering. A gap below a sell stop uses the opening price, then adverse exit slippage. Stop/target candle excursions no longer include movement past the assumed exit.
- Breakeven is calculated using the trade's stored fees and the exact exit-slippage formula. It is armed only below the observed market and above the existing stop. Gaps can still turn a breakeven stop into a loss.
- Fees are still a flat assumed rate; funding, variable exit liquidity and actual manual fills are not reconstructed. R keeps its existing denominator (initial price risk plus assumed fees), so a stop including slippage can be worse than -1R.

## Entry and manual instructions

- Live estimated buy price must satisfy the same structure/extension limits as the closed-bar setup. Reclaimed candidates must also satisfy their original reclaim price ceiling.
- The book timestamp is captured when the depth request completes, before waiting for OI/history. Quotes older than `MAX_ENTRY_QUOTE_AGE_MS` are blocked before insertion and rechecked before Telegram delivery. This is an age limit, not a guarantee that the quote remains available.
- FIRE includes a bounded entry zone and expiry. Its upper price also preserves the minimum net reward/risk against the original stop and TP1. Skip after expiry, outside the zone, or after stop/target was already touched.
- TP1 explicitly closes 100% of the paper position. TP2 is retained in storage for compatibility but is removed from the actionable message because no TP2 position is simulated.
- Breakeven updates now generate a stop-change instruction. Pending delivery is saved in the existing setup JSON and retried, including after restart or when no new candle is available. Delivery is at least once: a send followed by a failed database acknowledgement can repeat an instruction. Existing higher stops must never be lowered.
- The entry score is labelled “Setup score”, not calibrated confidence. Exit messages show the recorded paper exit price/time; users must not assume this is their executable current price.

## Monitoring

- A separate monitor loop runs independently of universe scans. A shared in-process lock prevents overlapping evaluations. The scanner also checks positions before its refresh, so a refresh failure cannot skip that cycle's check.
- Exit replay uses its own cursor; manipulation indicators get a separate current 90-candle window. Deterministic exits and stop progress are persisted before live risk requests. A risk-data failure is logged and does not undo those updates.
- After a prolonged outage, replay advances through up to 500 returned bars per poll. Current-market manipulation exits wait until replay reaches the current feature candle, avoiding skipping an earlier stop/target.
- Pending outcome retries are limited to one per poll so a notification backlog cannot consume an entire cycle. External API failures can still delay monitoring; this is not an exchange-hosted protective order.
- Run one worker instance. The monitor lock is in-process; distributed ownership/leases are not introduced by this patch. The existing database open-position uniqueness constraint remains in effect.

## Configuration and rollout

No SQL migration is required. New metadata uses the existing setup JSON column.

| Variable | Default | Purpose |
|---|---:|---|
| `TRADE_MONITOR_INTERVAL_MS` | 10000 | Independent monitor cadence; allowed 5000–60000 |
| `MAX_ENTRY_QUOTE_AGE_MS` | 5000 | Maximum book age before saving/sending a signal; allowed 1000–15000 |
| `MANUAL_ENTRY_TTL_SEC` | 30 | Entry validity from book observation; allowed 5–60 |

These are operational defaults, not optimized trading parameters. Keep `PAPER_MODE=true` for validation. Merge/deploy separately after review, verify the worker reports 6.9.10, and inspect the first new trade's execution-model tag, entry bounds, stop updates and exit. Historical metrics will not be repaired by deployment.

The evaluator test file previously duplicated the implementation without assertions. It is replaced with direct regression tests. Additional strategy, monitor and Telegram tests cover live-price bounds, gaps, first-candle ambiguity, stop-message retry, risk-history loading, API failures, overlapping polls and manual instructions. Run `npm ci` and `npm test` to reproduce the checks.
