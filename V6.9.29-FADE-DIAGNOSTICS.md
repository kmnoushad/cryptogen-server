# v6.9.29 — read-only fade funnel trace

On AWS, run `sudo /usr/bin/node --env-file=/etc/nexio-fade.env scripts/fade-diagnostics.js`
from `/opt/nexio`. The script reads the last 24 hours of Railway warning events
and AWS handoff events from Supabase, the current BTC gate, account risk and
calendar availability. It does not acquire a lease, write to Supabase, change
account modes, place orders or modify an active trade. It can run without
restarting the live worker.

The scanner only examines perpetuals with at least an 8% positive 24h move,
$15m in quote volume, and a top-20 volume rank before applying its failed-high
pattern. An all-red alt market can therefore produce no fade warnings. A
Finnhub HTTP 401, missing key or no verified event calendar blocks otherwise
eligible live entries. Do not treat these as evidence of a profitable setup.

Signal-specific OI/funding, book, sizing, expiry and other execution checks
remain after the read-only trace. A future revision can add safe reason counts
if the trace finds healthy warnings and handoffs but no orders.
