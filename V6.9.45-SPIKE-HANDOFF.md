# v6.9.45 spike candidate handoff

This update addresses a delivery/observability gap in the Binance live spike Fade worker.

## Changes

- Fresh tick candidates are processed before the routine polling pass, so they do not wait behind a slow routine reconciliation.
- If a candidate wake-up arrives while the worker is busy, the worker schedules an immediate follow-up tick instead of dropping the wake-up.
- The routine reconciliation/protection pass still runs on every worker cycle. Each candidate still goes through lease, account reconciliation, BTC/risk checks, quote validation, sizing, and native protection before an order can be submitted.
- `/fadeauto` reports per-symbol ready/warming/quiet/unseen counts, the most common detector gate among ready symbols, and the last candidate's authorization/block reason.
- Signal thresholds and risk sizing are unchanged. This is a delivery/diagnostic fix, not evidence of a profitable strategy.

## Deploy after PR #32 is merged

On AWS, pause entries first with `/fadepause` if practical. Then:

```bash
cd /opt/nexio
sudo systemctl stop nexio-fade
sudo git -C /opt/nexio fetch origin main
sudo git -C /opt/nexio merge --ff-only origin/main
sudo npm --prefix /opt/nexio ci --omit=dev
sudo /usr/bin/node --env-file=/etc/nexio-fade.env /opt/nexio/scripts/fade-preflight.js
sudo systemctl start nexio-fade
sudo systemctl status nexio-fade --no-pager -l
sudo journalctl -u nexio-fade --since "2 minutes ago" --no-pager
```

Check the journal for `NEXIO 6.9.45 external fade worker`, then check `/fadeauto`. The new health text should show detector readiness and the last candidate gate. Resume only after confirming the worker has a heartbeat and Binance reconciliation succeeds. Updating/restarting this worker does not update Railway's scanner service.

No exchange orders are created by this update or its preflight. Mock tests do not prove live fills or profitability.
