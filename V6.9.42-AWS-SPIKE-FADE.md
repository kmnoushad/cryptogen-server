# v6.9.42 AWS spike Fade execution

User-requested experimental live entry source. Profitability is unproven; implementation tests do not establish an edge. Defaults to the existing `legacy` signal source. Set `FADE_ENTRY_SOURCE=spike` in the existing AWS Fade environment file to select direct tick-driven entries. No changes to Futures Auto, Gold or Railway configuration are required.

## Behavior

AWS subscribes to aggregate trades on Binance's `/market` stream and bid/ask book tickers on `/public`. At startup and hourly reconnect it selects up to 40 trading USDT coin perpetuals with at least $15m 24-hour quote volume, ordered by volume, excluding BTC. It does not require an 8% 24-hour gain. This is a bounded liquid universe, not every listed coin. After disconnect it clears patterns and quotes and warms up again; no historic signals replay.

A 2% rise within 30 seconds with three times baseline quote flow starts a WATCH. After at least 140 seconds of continuous trade history, a 0.5–0.9% rejection, two seconds without a new high, and at least 60% sell-aggressor share over five seconds can produce a candidate. Strong/positive 15-minute BTC blocks it; fresh 30-second BTC strength also blocks it. Weak BTC does not establish fraud or a rug pull.

Candidates immediately wake the same serialized worker loop. Existing position protection runs first. Pause/control, fenced journal, idempotent orders, independent fresh account reads, events, OI/funding, max-three positions, structural stop and modeled-cost checks remain mandatory. Before the entry POST it rechecks live stream generation, BTC, fresh spread, pause and signal age. Candidates expire after ten seconds rather than wait for recovery. A failed feed does not stop protection for positions already open.

Spike mode ignores Railway's legacy execution handoffs; Railway warnings still run. `legacy` restores those handoffs. The production stop uses the existing tick-rounded resistance buffer; it is not widened to consume a dollar allowance. Planned risk is capped at **min($5, 0.5% equity)**. At $187.81 equity this is approximately $0.94. Market gaps, liquidation and fees can exceed a modeled allowance. Existing 75% partial target/25% runner and loss/cooldown rules remain unchanged.

## Deployment without replacing the current working copy

Create an isolated Git worktree for the deployment branch so AWS-only edits and Futures/Gold files stay at their existing paths. Install dependencies there and run Fade preflight with the existing environment file. Preflight reads the account and tables only; it does not verify order acceptance or profitability. Add `FADE_ENTRY_SOURCE=spike` to `/etc/nexio-fade.env`; do not expose or replace secrets.

Use a systemd drop-in for `nexio-fade` only, setting `WorkingDirectory` to the new worktree and clearing/replacing `ExecStart` with `/usr/bin/node <worktree>/src/fade-worker.js`. Existing service user, environment-file settings and restart policy remain inherited. Reload systemd and restart Fade only. Confirm v6.9.42/source=spike in logs and `/fadeauto` for connected stream, acknowledgement and account reconciliation. `/fadepause` blocks new entries; stop protection continues.

Rollback: set `FADE_ENTRY_SOURCE=legacy` and restart, or remove only this update's systemd drop-in, reload and restart. Do not delete other drop-ins or the environment file. Existing bot positions remain in the same account, Supabase scope and journal across source changes.

## Validation and limitations

Focused tests cover early WATCH, rejection, BTC/book invalidation, expiration, reset/generation fencing, source replacement, pause, protection-first order, no POST when source authorization expires, and the $5 ceiling. Unit/integration tests use mocked exchange and streams. No live orders were placed during implementation, and no AWS deployment was performed from this workspace. Historical minute candles cannot validate tick-level fills or profitability. Testnet stream routing and actual stop/partial/restart drills must be checked on the target host; data failures block entries.
