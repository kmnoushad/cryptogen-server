# v6.9.25 — multi-day fade loss and realized-profit giveback lock

The account audit showed 103 verified closed bot jobs (46W/57L) over seven
days: realized -$16.98, commission -$13.63, funding -$0.49, net -$31.11.
Within the 7-day income window, realized net peaked at approximately +$21.03
before giving back $52.13. These results predate v6.9.24 protection; they do
not measure whether that newer rule would have changed actual fills.

The v6.9.24 daily realized giveback lock cannot prevent losses accumulated
across several Dubai days. This release adds an entry-only rolling 7-day lock
using paginated Binance REALIZED_PNL, COMMISSION and FUNDING_FEE records:

- If net USDT income peaked at least max($10, 5% of current equity) and then
  gave back max($5, 3% of current equity), new entries stop.
- If 7-day net income is below minus max($10, 5% of current equity), new
  entries also stop even without a preceding profit peak.
- A Telegram warning is sent when either condition is observed, including
  when there is no bearish BTC signal. `/fadeauto` shows the gate reason.
- Deposits and withdrawals do not count as trading income. The seven-day
  window rolls forward automatically. Open positions continue reconciliation
  and native-stop monitoring; no liquidation is caused by this guard.

**The reported -$31.11 is already beyond the new rolling loss limit on the
reported equity. Expect new entries to be blocked after the AWS worker runs
v6.9.25 until old losses leave the 7-day window or conditions change.** Do
not add deposits merely to push the equity-based threshold higher. The
rules cap additional exposure but cannot turn a losing strategy profitable.

Pull and run the read-only audit on AWS with positions and protective orders
checked in Binance; this is separate from Railway's automatic deployment:

```sh
cd /opt/nexio
sudo git -C /opt/nexio pull --ff-only origin main
sudo npm ci --omit=dev
sudo /usr/bin/node --env-file=/etc/nexio-fade.env scripts/fade-performance.js
sudo /usr/bin/node --env-file=/etc/nexio-fade.env scripts/fade-preflight.js
sudo systemctl restart nexio-fade
sudo journalctl -u nexio-fade -n 20 --no-pager
```

The audit and preflight are read-only. Restarting the worker briefly interrupts
software monitoring; any existing Binance native stop must be verified first.
Confirm the startup version and fresh `/fadeauto` reconciliation afterward.
Historical jobs labelled `EXCHANGE_EXIT` can reflect native stop or take
profit: the journal alone cannot identify which filled. Old jobs have no
sampled floating-profit high; these data cannot prove whether individual
losers were previously winning.
