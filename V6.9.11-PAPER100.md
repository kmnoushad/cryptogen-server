# v6.9.11 — virtual $100 partial-profit experiment

This release implements the agreed **paper-first** test. It does not implement
Binance signed orders, Testnet order execution, API keys, deposits, withdrawals,
or live trading. Do not deposit funds or manually follow these experiment messages.

## Enable after merging and deploying

Set these Railway service variables and deploy the change:

```dotenv
PAPER_MODE=true
PAPER_100_TEST=true
```

`PAPER_100_TEST` defaults to false. Combining it with `PAPER_MODE=false` fails at
startup. No database migration is required; the ledger is stored in the existing
`nexio_trades.setup` JSONB field. Existing data is not modified.

Run **one Railway worker/replica only**, with the existing
`nexio_one_open_trade_global` unique index from `sql/schema.sql` installed.
Distributed worker ownership is not implemented. The existing monitor runs before
scans and independently on its 10-second default interval.

Verify the Telegram startup message says **v6.9.11** and
**VIRTUAL $100 TEST ON**. Send `/paperstats` (or `/statsnew`) and `/status`.
Before the first entry, the report should show $100, zero trades, and N/A win rate.
`/stats` also routes to this report while enabled. When disabled, `/stats` reports
legacy trades excluding this experiment, while `/paperstats` retains its history.

## Fixed experiment rules

- Starting virtual cash ledger: $100, carried across restarts, not reset daily.
- One open Futures position globally, including an older open paper trade.
- Planned stop risk: minimum of $1, 1% of current realized ledger balance,
  remaining daily allowance, and remaining rolling-seven-day allowance.
- Size from structural stop distance plus estimated entry/exit fees and adverse
  exit slippage. Stop rounded down to price tick, quantity rounded down to lot step.
- Maximum 2x simulated exposure, total notional capped at $200, with entry fees
  reserved alongside margin. Never enlarge a position to meet an exchange minimum.
- At +1.2 planned net R (estimated full-position liquidation profit), sell approximately
  80%, rounded down. Move the remainder's stop to its fee/slippage-adjusted breakeven.
- Trail at 0.5 initial cost-inclusive risk units below the closed price, effective
  from the next bar. A 0.5R giveback from the observed peak exits the runner at close.
- If the partial or remainder fails conservative size/notional checks, close 100%
  at the +1.2R trigger instead. Some exchange reduce-only exemptions could permit
  smaller exits; this simulator deliberately does not depend on them.
- Full exit after 120 minutes if not already closed. Existing manipulation-risk
  exits can close the remaining quantity earlier.
- At most five non-cancelled entries per Dubai calendar day; stop new entries after
  three consecutive losing closes within that day, daily realized loss of $3, or
  rolling-seven-day realized loss of $7. These are entry gates, not guaranteed loss
  caps: gaps can exceed the planned loss. No martingale, averaging down or hedging.
- Existing BTC, shock, setup, event-window and symbol-cooldown filters remain in
  force. No eligible FIRE means no simulated entry; radar pings are not trades.

The experimental exit replaces the old TP1/early-breakeven/pre-partial momentum-fade
rules for tagged trades only. Original TP fields remain stored for compatibility,
but experimental alerts display the actual partial-profit trigger. Old open trades
continue using their original evaluator. Disabling the flag stops new experimental
entries but still monitors any existing tagged position; it does not reset its ledger.
The old alert strategy resumes for future entries when the flag is disabled.

## Accounting and notifications

Experiment ID: `paper100-runner-v1`.
Execution model: `paper100-closed-bar-v1`.

`setup.paperTest` stores initial quantity, remaining quantity, planned dollar risk,
notional, cost assumptions, partial fill, and an append-only per-trade fill ledger.
Entry fees are charged on entry notional, exit fees on each actual simulated exit
notional. Cost assumptions are frozen per trade. Partial gains count immediately;
final PnL includes every exit and the original entry fee exactly once. Exit price
in the database is the quantity-weighted average of **all** exits, not the last fill.

The account report pages the complete cohort rather than only the last 200 trades.
It excludes older trades, cancelled entries and Alpha trades. Cash-ledger balance
excludes unrealized PnL and does not subtract reserved margin; it is not free margin
or mark-to-market equity. Reported drawdown is realized-ledger drawdown, not intrabar
equity drawdown. R uses the initial cost-inclusive dollar stop risk.

Progress is saved before Telegram messages; partial notifications retry after send
failure or restart without repeating fills. Delivery is at-least-once: if send
succeeds but acknowledgement fails, a duplicate notification remains possible.
If partial and final exits occur in the same replay batch, the final report includes
the partial result instead of sending a stale standalone partial notice.

## Simulation limitations and operational issues

- Live public Binance market data, but only closed one-minute OHLC candles for exits.
  This cannot prove a fleeting intraminute profit was executable. The monitor interval
  does not turn one-minute bars into tick-level execution.
- Pre-entry partial candles use only their close; earlier extremes are ignored.
- Existing stop wins when a candle touches both stop and target. If a candle touches
  the partial target and new breakeven level, assume the remainder stopped afterward
  (or at a worse close). This conservative assumption can understate results.
- Gap stops fill at the worse of the stop and candle open, then adverse slippage.
- Funding payments, liquidation engine, exchange queuing, fill latency, and real
  partial order fills are not simulated. Live minimum-size behavior may differ.
- Existing order-book entry estimate uses $200 notional, even for a smaller sized
  position; entry impact can consequently be overstated.
- Daily/weekly loss limits gate **new entries** using realized ledger changes. They
  do not guarantee that mark-to-market equity never crosses these levels.
- `/pause` stops new scanning entries but continues monitoring; it is in-memory and
  does not survive a restart. There is no live execution kill switch in this release.
- The reported Finnhub 401 and BTC recorder missing-table issues are not repaired
  here. An unavailable calendar means incomplete event coverage; do not treat a clear
  event guard as verified absence of events. Fix those separately before live use.

The test has no proven edge. These engineering tests validate accounting and control
flow, not profitability. Neither a fixed win-rate threshold nor 100 trades alone
establishes live suitability. Review fresh out-of-sample results across regimes,
cost sensitivity and equity drawdown before deciding whether to build exchange execution.
There is no concurrent A/B baseline in this release.
